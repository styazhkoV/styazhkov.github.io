## Проблема

Нужно было запустить продукт для онлайн-автокредитования без традиционных ручных этапов и лишних бюрократических проверок. Требовалось сократить время на оформление и одновременно сохранить качество допустимых рисков.

## Решение

Я проектировал клиентский путь, описывал как бизнес-требования, так и интеграционную модель: анкета, проверка данных, статус заявки, валидация ИИН, логика принятия решения и маршрутизация результатов. Это позволило сделать продукт понятным для команды разработки и для комплаенса.

<Mermaid code={`sequenceDiagram
  participant C as Client
  participant API as Credit API

  C->>API: Submit loan form

  O->>D: Risk checks
  D-->>API: Decision status

## Что было ключевым

- унификация требований для NEW, B2C и C2C;
- проектирование сервисного сценария без ЭЦП и биометрии;
- проверка данных и статусов через Postman, SQL и ELK.

## Результаты

- продукт запущен в рабочем режиме;
- клиентский путь стал более коротким и прозрачным;
- качество данных улучшилось за счёт оптимизаций валидации и дедупликации.
